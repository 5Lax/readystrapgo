# Builder audit before v2

Audited 2026-10-16. ReadyStrapGo baseline `ce6216d`; StrapBuilder reference `55fcd04`. Line references below refer to those revisions, not the replacement files. The reference clone was read only; runtime checks used a disposable copy under `/tmp`.

## ReadyStrapGo

- **Catalog failure leaves a dead-end wizard.** `src/app/builder/page.tsx:124-144` only toasts fetch errors, without retry or fallback. `:150-153` derives every width from that response. Reproduced with placeholder Supabase environment variables: chose Sternum Strap, continued to Dimensions, and found zero width buttons; Continue stays disabled. There is no catch/finally for a thrown action either. `src/lib/supabase/middleware.ts:10-12` also assumes credentials exist, preventing an unconfigured checkout from rendering at all.
- **Save Quote is a false success.** `src/app/builder/page.tsx:939-946` only shows “Quote saved!”; it makes no insert or intake call. No project or quote is persisted.
- **No drawing, exports, ends, or logo configuration.** The entire render dispatch at `src/app/builder/page.tsx:974-984` consists of five option/quote panels. Type is cosmetic: `:227-234` never sends it to pricing. No SVG, print, JSON, or production spec is built.
- **Width changes leave incompatible selected hardware.** `src/app/builder/page.tsx:429-433` clears webbing/color but retains `selectedHardware`; `:169-186` filters only the picker. There is no material/hardware compatibility rule. `:203-204` unconditionally allows the hardware step.
- **Pricing is delayed and can become stale.** `src/app/builder/page.tsx:216-243` only prices on step 5, omits color from dependencies, retains old results on errors, and has no cancellation/request ordering for concurrent calculations. `:943` enables Save whenever any previous result exists.
- **Input validation is incomplete.** `src/app/builder/page.tsx:195-210` validates only the current step. `src/lib/actions/catalog.ts:194-228` accepts unvalidated quantities, lengths, plies, colors, and part IDs; `:248-274` silently skips absent parts. There is no authoritative compatibility validation at the quote boundary.
- **Unavailable materials can be priced as free.** `src/lib/actions/catalog.ts:238-239` defaults missing regional rates to zero and `:310` marks every quote available. `:235` checks only the regional MOQ, ignoring `webbing.moq_by_region`. `:297-299` estimates shipping with webbing weight only, omitting hardware.
- **Two existing pricing implementations.** The builder uses `src/lib/actions/catalog.ts:194`; `src/lib/pricing.ts:47` is a separate fixed-price retail calculator with different rates/discounts. V2 must consistently use the catalog engine, not switch between them.
- **Intake schema is incomplete in this checkout.** Existing intake at `src/app/upload/page.tsx:556-594` calls `generate_sample_number` then inserts `projects`; `:610-619` inserts attachments into `project_files`. None of those definitions is in the checked-in migrations. `supabase/migrations/002_create_quotes.sql:2-12` defines authenticated quotes, not this anonymous project intake. A fresh database needs the existing deployed intake schema in addition to the catalog migrations. V2 reuses that intake contract and reports backend failures; a live persistence check requires a configured database.

## StrapBuilder reference

- **Loading a template does not place parts.** `client/src/store/useConfig.ts:198-235` creates instances without `canvasPosition` or `placedOnCanvas`. `client/src/components/Canvas2D.tsx:808-809` renders only placed instances. Browser verification: selecting Dog Collar — Basic yields zero `[data-instance-id]` elements on the drawing.
- **Carry Handle crashes to white.** `client/src/data/templates/handle.json:26-27` references `d_ring_38mm_steel`, absent from `client/src/data/catalog.json`. `client/src/pages/builder.tsx:119-130` asserts that the lookup succeeded and dereferences `component.cost`; the template branch at `:146-150` similarly dereferences missing parts. `client/src/App.tsx:18-28` has no error boundary. Browser verification: selecting Carry Handle throws `Cannot read properties of undefined (reading 'cost')`; body becomes empty.
- **PDF is a toast; Email and Submit are absent.** `client/src/pages/builder.tsx:213-217` says PDF generation is coming soon. `client/src/components/DownloadButtons.tsx:34-45` renders Email only when a callback is passed; `client/src/pages/builder.tsx:468-471` passes none. There is no submission handler in the builder.
- **JSON is wired, but exports the wrong model.** Correction to the reported blocker: `client/src/pages/builder.tsx:220-229` really downloads a JSON Blob with FileSaver. It serializes `config`, not `components`, their edited properties/connections, or `modularQuantity`. Thus the visible modular build is not exported. This is data loss rather than a missing click handler.
- **Drawing is not to scale.** `client/src/components/Canvas2D.tsx:403-404` uses width × 0.225 and length × 0.15; template width receives a further transform in the rect at `:444-445`. Modular dimensions at `:595,615` also use different axis factors. Hardware uses a separate arbitrary size at `:456`. A 25 × 480 mm strap does not retain its physical aspect ratio.
- **Two modes produce different prices and quantities.** `client/src/lib/pricing.ts:7-51` uses length-based labor, volume markup, and $0.05 rounding. `client/src/pages/builder.tsx:168-200` uses $0.50 labor per component with no markup in modular mode. `client/src/store/useConfig.ts:231-234` does not carry template quantity into `modularQuantity`. Browser verification: initial collar is $3.35 at 250 units; selecting the same template changes it to $3.84 at 100 units. Different formulas remain even if quantities are equalized.
- **Phone canvas collapses.** `client/src/pages/builder.tsx:278-280,414,455` lays out two non-shrinking 320px sidebars and a `min-w-0` flexible main in one row with no mobile breakpoint. Browser verification at 375 × 812: main bounds `{x:352, y:268, width:0, height:528}`.

## Verification method

Ran `npm install` and `npm run dev` in the worktree using placeholder environment variables, without creating an environment file. Used Playwright with local Chrome to exercise the original wizard and the temporary reference app. The existing dev process had stalled after dependency installation; restarting with filesystem watch access resolved local 404s. Supabase was not configured, so original successful catalog/quote paths were audited from source, not claimed as live database tests.
